# Pip — 产品需求文档

> 本文档回答「Pip 长什么样、怎么用、看起来是什么感觉」。

## 1. 一句话

**Pip 是一个安静的打卡日历。想打卡的时候，在日历上留一个点。**

slogan：`A pip a day.`

它不是习惯养成工具，不催你、不评价你、不给你算连续多少天。它只是一张挂在墙上的日历，你做了就点一下，仅此而已。

## 2. 用户与场景

**用户**：我自己，加上几个朋友。个位数，都是熟人，都在中国大陆，都用手机。

**不是**面向陌生人的产品：没有注册、没有引导流程、没有分享裂变。分发方式是把链接丢进微信群。

**典型场景**：

| 场景 | 用户动作 |
|---|---|
| 睡前想起来今天没记 | 点开主屏幕图标 → 点今天 → 勾掉做了的 → 关掉 |
| 白天刚做完一件事 | 同上，20 秒内完成 |
| 想补记昨天 | 点昨天那格 → 补勾 |
| 翻看这个月 | 上下滑一滑，看小点的疏密 |
| 想加一个新习惯 | 进管理页 → 新建 |

**核心情绪目标**：打开时没有压力。看到空着的格子不焦虑，看到点多了不亢奋。

## 3. 非目标（明确不做）

- 提醒、通知、倒计时、连击天数、成就徽章
- 社交、好友、排行榜、分享打卡结果
- 账号、登录、多设备同步（推迟，见 DESIGN.md）
- 目标设定、量化指标（「每天 8 杯水」这类）
- 统计分析、图表、趋势线
- 后台数据、运营、埋点

**判断新需求是否该做的标准**：它会不会让用户打开时产生压力？会，就不做。

## 4. 产品形态

**Web 应用（PWA），纯静态，无后端。**

- 单个 HTML 页面 + 少量 JS/CSS，无构建工具、无框架
- 数据只存在用户本机的 localStorage 里，不上传任何地方
- 通过浏览器「添加到主屏幕」装成 App，全屏运行，无浏览器地址栏
- 装好后离线可用，日常打开不需要联网
- 没有「用户」概念：一台设备就是一份数据

**形态约束**：

- **移动优先**，竖屏，单手可达。桌面浏览器能用但不是优化目标
- 目标环境：iOS Safari 16+、Android Chrome。其他现代浏览器应可用，不专门适配
- 界面语言只有中文。产品名与代码标识用 `Pip` / `pip`
- 首次安装依赖网络可达（GitHub Pages 在国内的首次可达性是 go/no-go 项，见 DESIGN.md）

**分发动线**（微信场景）：群里发链接 → 提示「右上角在浏览器中打开」→ 添加到主屏幕 → 只用主屏幕图标打开。

> 应用内需要一页简短图文说明，讲清楚「必须添加到主屏幕」和「别在 Safari 里也打卡」——因为 iOS 主屏幕应用有独立存储，混用会产生两份数据。

## 5. 信息架构

只有**两个主屏幕**加**一个面板**。刻意保持这么少。

```
汇总日历（首页）
├── 当天清单 ─── bottom sheet，点日历格子滑出
└── 管理页 ───── 右上角入口
    ├── 打卡项列表（新建 / 编辑 / 排序 / 删除）
    ├── 单项日历（点某一项进入）
    └── 数据（导出 / 导入 / 导出提醒）
```

没有底部 tab bar，没有汉堡菜单。因为页面总数是 3，任何导航控件都比内容本身更重。

## 6. 页面与交互

### 6.1 汇总日历（首页）

**布局**（从上到下）：

1. **月份栏**：`2026年9月`，左侧 `‹` 右侧 `›` 切换月份；右侧最边上还有一个「管理」入口图标
2. **周表头**：`一 二 三 四 五 六 日`（**周一起始**）
3. **日期网格**：固定 **6 行 × 7 列**。固定 6 行是为了切换月份时高度不跳动
4. 底部留白，不放任何东西

**日期格子**：

```
┌──────────┐
│    22    │  ← 日期数字
│  ● ● ●   │  ← 当天的 pips，最多 3 个
└──────────┘     超出显示 +N
```

**格子状态**：

| 状态 | 表现 | 可点 |
|---|---|---|
| 平常日期 | 数字用次级文字色 | 是 |
| **今天** | 数字加粗 + 强调色，格子铺一层极淡的强调底色 | 是 |
| 已打卡 | 底部显示彩色 pips | 是 |
| 未来日期 | 数字用最浅的三级文字色 | **否**，置灰 |
| 非本月 | 不渲染，留空 | — |
| 按下 | 格子短暂出现浅灰底色 | — |

**交互决策：未来日期不可点。** 打卡是记录已发生的事，不是立计划。允许点未来会带来「我到底打没打」的歧义，也违背「不做计划工具」的定位。反过来，**过去的日期一律可点**，因为补记是很自然的需求。

**初始视图**：打开就是当月，今天所在的那一格高亮。不记忆上次浏览的月份——打开永远回到现在。

**月份切换**：点箭头或左右滑动网格。允许滑到未来月份（可以看，但格子都置灰）。

### 6.2 当天清单（bottom sheet）

**触发**：点日历上的某个日期格子。

**形态**：从底部滑出的面板，初始高度约占屏幕 60%，可上拖展开到 90%。点遮罩或下滑关闭。

**内容**：

```
─────────────────────
        9月22日 周一        ✕
─────────────────────
  🏃  跑步                    ○     ← 未打卡
  💧  喝水                    ●     ← 已打卡
  📖  读书                    ○
─────────────────────
```

**每行**：左侧 emoji 图标 + 标题，右侧一个圆圈表示状态（空心 = 未打卡，实心填该打卡项的颜色 = 已打卡）。

**交互**：

- **点整行** = 立刻切换打卡状态，**不弹确认框**，无动画阻塞
- 打卡瞬间，圆圈填色并轻微回弹（200ms）。**不弹提示、不庆祝、不显示「已打卡 3 天」**
- 已打卡的行**不加删除线、不置灰**。打卡是「完成」不是「划掉」，要保持正反馈的平静
- **长按某一行（500ms）** = 展开该行的备注输入框，就地编辑
- 点日期标题旁的 `✕` 或下滑关闭

**关于「当天备注」的一处修正**：

DESIGN.md 的交互部分写「底部写当天备注」，但数据模型里 `note` 挂在 `pips` 下——也就是**每个打卡项、每天各有一条备注**，并不存在「当天总备注」这个字段。

**采用后者（每项每天的备注）**，理由：

- 数据模型已经支持，不需要改结构
- 语义更准：「今天跑了 5 公里」属于跑步，不属于「9月22日」这个日期
- 与「备注放长按」的设计吻合，不用在面板底部再放一个含义模糊的输入框

因此 DESIGN.md 第 28 行「底部写当天备注」需修正为「长按某行写该天的备注」。PRD 以本节为准。

**空状态**：如果还没有任何打卡项，面板显示「还没有打卡项」+ 一个「新建」按钮，点了直接跳管理页新建。

### 6.3 管理页

**入口**：日历页右上角图标。

一个页面装下两件事：上半是打卡项，下半是数据。

**打卡项列表**：每行显示颜色圆点 + emoji + 标题 + 总备注（一行截断）。支持长按拖拽排序。

**新建**：列表末尾一行「+ 新建打卡项」，样式与普通行一致但文字用次级色。**不用悬浮 FAB**——FAB 会在日历页造成视觉噪音，而新建是个低频动作。

**编辑**（点某一行）：弹出编辑面板，字段为：

- 标题（必填，纯文本，最长 20 字）
- 总备注（可选，说明这一项是什么，最长 100 字）
- 颜色（8 色预设色板，单选）
- 图标（emoji，可选；不填则只显示颜色圆点）
- 删除（面板底部，红色文字）

**删除是唯一需要二次确认的操作**（弹一个确认对话框）。原则是：**可逆的操作不确认，不可逆的才确认**。切换打卡状态随时可以再点一下撤销，所以不弹框；删除打卡项会连同它所有历史记录一起消失，所以必须确认。

### 6.4 单项日历

点管理页里某一项进入，显示这个打卡项自己的月历：打过卡的日期用该打卡项的颜色填满整格，其余留空。

顶部显示这一项的累计天数（例如 `共 34 天`）。

**只显示总天数，不显示连续天数**——连续天数就是连击，明确不做。

### 6.5 数据

在管理页底部：

- **导出 JSON**：下载一个文件
- **导入 JSON**：选文件，然后选「合并」或「覆盖」，**默认合并**
- **导出提醒**：显示「上次导出：12 天前」，超过 30 天变红

导出提醒必须是常驻可见的，不能只藏在设置深处。数据在浏览器里而不在用户手里，清缓存、换手机、卸载都会永久消失，而我没有能力代为恢复。

## 7. UI 风格

### 7.1 设计原则

**日历是主角，颜色是唯一的装饰，其余一切退让。**

产品的个性全部由那些彩色小点承担。所以底色、文字、线条必须极度克制——一旦界面本身开始抢眼，小点就不显眼了。

三条具体准则：

1. **不用阴影做层次**，用底色深浅和留白。整个应用只有 bottom sheet 允许有一层投影
2. **不用边框划分区块**，用间距
3. **不用纯黑纯白**。用暖调的中性色，像纸，不像屏幕

### 7.2 色彩

**基础色板**（CSS 变量，`prefers-color-scheme` 切换）：

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `#F7F6F3` | `#131211` | 页面底色，暖纸白 / 暖近黑 |
| `--surface` | `#FFFFFF` | `#1E1C1A` | 面板、sheet 抬起层 |
| `--text` | `#1C1B19` | `#F2F0EC` | 主文字 |
| `--text-secondary` | `#6B6862` | `#9C9891` | 日期数字、次要说明 |
| `--text-tertiary` | `#A5A19A` | `#6E6A64` | 未来日期、周表头、占位符 |
| `--line` | `#E8E5DF` | `#2C2A27` | 分隔线（少用） |
| `--accent` | `#2E6B4F` | `#6FBF95` | 「今天」、主按钮 |
| `--accent-soft` | `#E4EEE8` | `#1F2C25` | 「今天」格子的淡底 |

强调色选**墨绿**而不是常见的蓝：蓝太像 SaaS 后台，绿更安静，也贴合「习惯生长」的意味。深色模式下换成亮一档的绿以保证可见度。

**打卡项色板**（8 个预设，用户单选）：

| 名称 | 色值 | | 名称 | 色值 |
|---|---|---|---|---|
| 珊瑚 | `#E8734A` | | 湖蓝 | `#4A8FBF` |
| 琥珀 | `#DFA32B` | | 靛紫 | `#7C6BB8` |
| 苔绿 | `#7A9E4A` | | 玫红 | `#D2607F` |
| 松绿 | `#3E8E7E` | | 石墨 | `#7A7671` |

全部取中明度，保证在浅底和深底上都可辨识。

**颜色不单独承载信息**：每个色点旁边始终有打卡项标题，单项日历里也有文字标签。色盲用户不依赖颜色也能用。

### 7.3 字体

系统字体栈，不加载网络字体（国内加载字体太慢，且会让首屏闪一下）：

```css
--font: -apple-system, BlinkMacSystemFont, "PingFang SC",
        "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif;
```

**日历数字必须用 `font-variant-numeric: tabular-nums`**，否则 1 比 8 窄，网格会看起来歪。

**字号阶梯**：

| 用途 | 字号 / 字重 |
|---|---|
| 月份标题 | 20px / 600 |
| 清单项标题 | 17px / 400 |
| 日期数字 | 15px / 500（今天 600） |
| 备注、次要文字 | 14px / 400 |
| 说明、周表头 | 13px / 400，周表头 12px / 500 |
| **输入框** | **16px（不得更小）** |

> 输入框字号低于 16px 时 iOS Safari 会在聚焦时自动放大页面，破坏布局。这是硬性下限。

### 7.4 尺寸与间距

- **间距阶梯**：4 / 8 / 12 / 16 / 20 / 24 / 32 px，只用这些值
- **页面左右边距**：16px
- **日历格子**：高度 ≥ 48px，375px 屏宽下每格约 49px 宽
- **所有可点区域 ≥ 44×44px**（iOS 触摸目标下限）
- **圆角**：格子 10px，卡片 / 面板 14px，bottom sheet 顶部 20px，按钮 10px，pip 为整圆

### 7.5 组件规范

**pip（日历格子里的彩色小点）**：直径 6px，间距 3px，整圆，最多 3 个；超出时第 3 个位置显示 `+N`（13px，`--text-tertiary`）。

**勾选圆圈（当天清单）**：直径 24px。未打卡为 1.5px 描边的空心圆，描边用 `--text-tertiary`；已打卡为实心填充打卡项颜色的圆。

**bottom sheet**：顶部 20px 圆角，`--surface` 底色，唯一允许的投影是 `0 -8px 24px rgba(0,0,0,.08)`。顶部有一个 36×4px 的拖拽指示条，颜色 `--line`。

**按钮**：主按钮为 `--accent` 实底 + 白字；次按钮为透明底 + `--text` 文字。没有描边按钮。

**图标**：不引入图标库。管理入口用内联 SVG（三条横线），其余全部用文字。打卡项的图标用 emoji，因为零成本、自带颜色、用户天然熟悉。

> emoji 在不同系统上渲染不一致，这是接受的代价——它出现在用户自己定义的位置，不一致反而不影响使用。

### 7.6 动效

克制。动效只用来解释「发生了什么」，不做装饰。

| 动作 | 时长 | 曲线 |
|---|---|---|
| 打卡：pip / 圆圈出现 | 200ms | `cubic-bezier(0.34, 1.56, 0.64, 1)`（轻微回弹） |
| 取消打卡：缩回消失 | 120ms | `ease-in` |
| bottom sheet 滑出 / 收起 | 240ms | `cubic-bezier(0.32, 0.72, 0, 1)` |
| 月份切换 | 180ms | `ease-out` |

**禁止**：庆祝动画、撒花、震动反馈、声音、Toast 提示「打卡成功」。点了就是点了。

必须响应 `prefers-reduced-motion: reduce`，此时所有位移与缩放降级为纯透明度过渡。

### 7.7 深色模式

**必须支持，跟随系统**（`prefers-color-scheme`），不提供手动开关。

理由：打卡的高频时段是晚上睡前，深色模式下打开不刺眼是真实需求，而不是加分项。跟随系统是因为这个应用轻到不该有「设置」这个概念。

深色模式下唯一的调整是强调色提亮（见 7.2 表），打卡项色板 8 色保持不变。

### 7.8 响应式

**手机优先**，375–430px 为设计基准。

桌面（≥ 768px）：整个应用居中，最大宽度 **480px**，两侧留白。日历保持 7 列不变形，格子变高一点。

不做平板/桌面的多栏布局。这不是目标场景。

## 9. 状态与异常

| 情况 | 处理 |
|---|---|
| **首次打开（无数据）** | 不预置任何示例打卡项。直接显示空日历 + 空状态引导，让用户自己建第一个 |
| **数据加载中** | 不做 loading 转圈。先渲染空日历骨架，数据到了再填 pips。本地读取极快，转圈只会造成闪烁 |
| **localStorage 解析失败** | 回退到 `pip:v1:backup`，**绝不自动写回**，提示用户数据可能损坏并引导导出。详见 DESIGN.md |
| **写入失败（配额 / 无痕）** | 明确提示「存储写入失败，请立即导出备份」，不要静默失败 |
| **导入文件格式不对** | 校验 `app` 和 `version` 字段，不匹配就明确说明原因，不要静默忽略 |
| **导入合并冲突** | 默认取并集。已知局限：并集无法传播「取消打卡」，接受这个语义漏洞 |

## 10. 可访问性

- 所有可点区域 ≥ 44×44px
- 正文对比度满足 WCAG AA（4.5:1）；pip 等纯装饰元素不受此限
- 颜色不单独承载信息（见 7.2）
- 响应 `prefers-reduced-motion`
- 语义化 HTML：日历用 `<table>` 或带 `role="grid"` 的结构，格子有可读的 `aria-label`（例如「9月22日，周一，已打卡 2 项」）
- 键盘可用：格子可 Tab 聚焦、回车打开清单。桌面不是重点，但不能不可用

## 11. 验收标准

v1 完成的判定：

1. 手机上添加到主屏幕后能全屏打开，离线可用
2. 能新建、编辑、删除、排序打卡项
3. 点日历格子能打开当天清单并切换打卡状态，刷新后仍在
4. 能长按写当天某项的备注，刷新后仍在
5. 日历上能正确显示 pips，超过 3 个显示 `+N`
6. 今天高亮、未来日期置灰不可点、周一是第一列
7. 深色模式下跟随系统正常显示
8. 导出 JSON 能拿到文件；导入能合并和覆盖
9. 超过 30 天没导出时，管理页显示红色提醒
10. **东八区晚上 8 点后打卡，记录在当天而不是第二天**（这是 `toISOString()` 陷阱的验收点）
