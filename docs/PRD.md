## 1. 一句话

**Pip 是一个安静的打卡日历。想打的时候，就在日历上留一个点。**

slogan：`A pip a day.`

**为什么叫 Pip**：骰子、骨牌上的那个小点就叫 pip，正好是「标记」的最小单位。短、好念、不撞同品类产品、气质轻，而且图标几乎不用设计——一个圆点就是全部。名字从交互里长出来，而不是贴上去。

**已排除的名字**（不要重新提议）：Tally（知名记账 app）、Dotcal（dotcal.co 是日历产品，同品类相撞）、Notch（Minecraft 作者 + 刘海屏，搜索污染）、Ledger（硬件钱包）、Marked（前端 markdown 库）。

## 2. 核心理念：记录，不是待办

这是整个产品最重要的一个区分，其他所有设计都由它推导出来。

**Pip 记录「你做了什么」，而不是「你还没做什么」。**

所以：

- 没有「预先定义好一份清单，做完一项勾掉一项」这回事
- 没有「今天还有 3 项没完成」这种暗示
- 打卡是**往这天添一笔记录**，不是**把一个格子从空变成满**
- 同一个模板一天可以打多次，每次都留下独立的一条记录

后果之一：**界面上不存在「未完成」这个概念**。日历上空着的格子什么都不说明，它只是还没被记录，不是「你失败了」。这是「打开没有压力」这个情绪目标的实现方式。

后果之二：**没有取消打卡，只有删除记录**。「取消打卡」预设了「本该打卡」，「删除记录」只是纠正一笔记错的事。措辞上必须严格区分。

判断新需求该不该做的标准：**它会不会让用户产生「我欠着什么」的感觉？** 会，就不做。

## 3. 用户与场景

**用户**：我自己，加上几个朋友。个位数，都是熟人，都在中国大陆，都用手机。

**不是**面向陌生人的产品：没有注册、没有引导流程、没有分享裂变。分发方式是把链接丢进微信群。

**典型场景**：

| 场景 | 用户动作 |
|---|---|
| 刚跑完步 | 点「Pip」→ 选跑步 → 写「5 公里」→ 确定 |
| 喝了杯水，顺手记一下 | 点「Pip」→ 选喝水 → 确定（不写备注） |
| 睡前回想今天 | 点今天 → 看当天记了几笔 |
| 想补记昨天 | 点昨天那格 → 底部「Pip一下」→ 选模板 |
| 翻看这个月 | 上下滑一滑，看点的疏密 |
| 想加个新习惯 | 点「模板」→ 新建 |

**核心情绪目标**：打开时没有压力。看到空着的格子不焦虑，看到点多了不亢奋。

## 4. 非目标（明确不做）

- 提醒、通知、倒计时、连击天数、成就徽章
- 社交、好友、排行榜、分享打卡结果
- 账号、登录、多设备同步（推迟。换设备用导出/导入做一次性迁移，见 TECH 9.3）
- 目标设定、量化指标（「每天 8 杯水」这类）
- 统计分析、图表、趋势线
- **任何形式的「完成度」「待办」「计划」概念**
- 后台数据、运营、埋点

> **关于「打卡统计」**：这个方向将来可能要做，但它和上面两条（「统计分析」和「任何形式的完成度概念」）直接冲突，所以先把边界定下来。
>
> **安全的统计**：回顾性的、没有目标的、不产生比较的。例如「这个月记了 47 笔」「跑步一共 34 次」——只是在陈述事实。
>
> **危险的统计**：任何带目标、比率或连续性的。例如「本月完成率 60%」「连续 12 天」「比上月少 12%」。这些不是统计，是**用数字包装的待办和评判**，正是本产品要避免的东西。
>
> 真要做之前，先想清楚「什么样的统计不制造压力」，再动手写代码。技术上怎么做见 [`TECH.md`](TECH.md) 6.5。

## 5. 产品形态

**Web 应用（PWA），纯静态，无后端。**

- 单个 HTML 页面 + 少量 JS/CSS，无构建工具、无框架
- 数据只存在用户本机的 localStorage 里，不上传任何地方
- 通过浏览器「添加到主屏幕」装成 App，全屏运行，无浏览器地址栏
- 装好后离线可用，日常打开不需要联网
- 没有「用户」概念：一台设备就是一份数据

**形态约束**：

- **移动优先**，竖屏，单手可达。桌面浏览器能用但不是优化目标
- 目标环境：iOS Safari 16+、Android Chrome
- 界面语言只有中文。产品名与代码标识用 `Pip` / `pip` / `template`
- 首次安装依赖网络可达（GitHub Pages 在国内的首次可达性是 go/no-go 项）

**分发动线**（微信场景）：群里发链接 → 提示「右上角在浏览器中打开」→ 添加到主屏幕 → 只用主屏幕图标打开。

> 应用内需要一页简短图文说明，讲清楚「必须添加到主屏幕」和「别在 Safari 里也打卡」——因为 iOS 主屏幕应用有独立存储，混用会产生两份数据。

### 备选形态（如果 Web 方案作废）

国内场景下，「把应用送到朋友手机上」这一步要么走微信，要么走域名 ICP 备案：

- **微信小程序**：主体备案免费，不用买域名和服务器，但需等 1–20 个工作日
- **域名 ICP 备案**：需国内服务器约 100–150 元/年，等 1–2 周

**小程序 + 微信云开发**是国内唯一同时满足「免费 + 速度快 + 跨设备同步」的组合，也是唯一能顺带解决多设备同步的路线。如果 GitHub Pages 的可达性验证失败，或将来「手机记了电脑看不到」真的成为痛点，转这条路线。

注意区分两种备案：小程序主体备案免费、不需域名和服务器；域名 ICP 备案要买服务器。

## 6. 信息架构与导航

**只有一个主屏：月历。** 底部固定一条工具栏，三个按钮。

```
                     ┌─ 打卡弹窗（选模板 → 写备注 → 确定）
月历（首页，常驻）─────┼─ 某日打卡列表 ── 打卡详情
                     ├─ 模板弹窗（新建 / 编辑 / 停用 / 删除）
                     └─ 设置页（切走整屏）
```

**底部工具栏**：`模板` / `Pip` / `设置` 三个按钮，常驻在底部。

- `模板` 和 `打卡` 是**弹窗**（屏幕中间的悬浮卡片），日历还在底下
- `设置` 是**切进设置界面**，整屏替换日历，设置页左上角有返回箭头回日历
- `打卡` 是主动作，视觉上要更突出（用强调色）

**没有第五个入口。** 页面总数就这么少，任何多余的导航控件都比内容本身更重。

## 7. 页面与交互

### 7.1 首页：月历

**布局**（从上到下）：

1. **月份栏**：`2026年9月` **居中**，两侧的 `‹` `›` 各占 44px 并**贴到屏幕两侧**，切换月份（见 9.5）
2. **周表头**：`一 二 三 四 五 六 日`（**周一起始**）
3. **日期网格**：固定 **6 行 × 7 列**。固定 6 行是为了切换月份时高度不跳动
4. **底部工具栏**：`模板` / `Pip` / `设置`

**日期格子**：

```
┌──────────┐
│    22    │  ← 日期数字
│  ●●●     │  ← 当天的 pips，最多两行共 8 个
│  ●●●     │
└──────────┘
```

**每个 pip 一个点**（不是每个模板一个点）。喝了 5 次水就有 5 个点，这天看着就「很满」——这正是想表达的信息。

**点的数量规则**：

| 当天记录数 | 显示 |
|---|---|
| 1–5 条 | 一行，全部显示 |
| 6–8 条 | 两行，尽量均分（3+3 / 4+3 / 4+4） |
| 超过 8 条 | 两行 **5 + 3**，第二行末尾显示 `+N`（N = 总数 − 8） |

两条约束决定了这个规则，都是实测出来的：

- **一行最多 5 个**。格子内宽 47.2px（iPhone 14 / 390px 屏实测），5 个点占 5×7 + 4×2 = 43px，余 2.1px；6 个要 52px，放不下。
- **有溢出时第二行只放 3 个**。`+N` 要占宽度：3 个点加 `+N` 是 46.2px（余 1px），4 个点加 `+N` 是 55.2px，溢出 8px。
- **行间距固定 2px，不能调大**。改成 3px，5 个点就是 47px，只剩 0.1px——任何一点误差都会溢出。

**6–8 条是均分而不是顺次填满**，因为顺次填会排成 5 + 1，第二行孤零零一个点。

**上限取 8 而不是「没溢出时 10、有溢出时 8」**，是为了让显示的点数随记录数单调不减——否则从 10 条变 11 条，点反而从 10 个掉到 8 个，看着像出了错。

**点的顺序**：按模板在模板列表中的顺序排列。这样同一个模板的颜色在每天的格子里位置一致，扫视时更容易认。

**点区的高度是固定的（两行）**，没有点的格子也保留这块空间。否则日期数字会随点行数上下浮动，两行点时偏差有十几像素，一眼就能看出没对齐。

**格子状态**：

| 状态 | 表现 | 可点 |
|---|---|---|
| 平常日期 | 数字用次级文字色 | 是 |
| **今天** | 数字套一个强调色**填充圆** + 反色文字（**不用描边环**） | 是 |
| 有打卡 | 底部显示彩色点 | 是 |
| 未来日期 | 数字用最浅的三级文字色 | **否**，置灰 |
| 非本月 | 不渲染，留空 | — |
| 按下 | 格子短暂出现浅灰底色 | — |

**未来日期不可点**：打卡是记录已发生的事，不是立计划。反过来**过去的日期一律可点**，因为补记是自然需求。

**初始视图**：打开就是当月，今天那格高亮。不记忆上次浏览的月份——打开永远回到现在。

**月份切换**：点箭头或左右滑动网格。允许滑到未来月份（可以看，但格子都置灰）。

### 7.2 打卡弹窗（底部「Pip」）

**这是产品的主操作，必须在 3 次触摸内完成。**

**第一步：选模板**

弹出 sheet，显示所有**启用中**的模板（已停用的不出现）。一模板一行：

```
┌─────────────────────────────┐
│  💧  喝水                ●  ›│
│  🏃  跑步                ●  ›│
│  📖  读书                ●  ›│
└─────────────────────────────┘
```

每行：emoji + 标题，右侧一个该模板颜色的圆点，最右是 `›`。没设 emoji 时左侧改用颜色圆点占位。

> **为什么是行不是方块**：行占满整宽，20 字的标题也看得全；方块一格只有约 90px 宽，四个中文字就截断了，而模板的名字是这里最要紧的信息。方块排得更密（同样高度约 14 个 vs 行约 10 个），但密不抵名字被截。

**还没有任何模板时**：显示「还没有模板」+「新建模板」按钮，点了直接进模板弹窗的新建流程。

**第二步：写备注并确定**

点一个模板后，sheet 切到第二步：

```
─────────────────────────
  💧  喝水          ← 已选模板
  今天 9月22日       ← 目标日期
─────────────────────────
  ┌─────────────────────┐
  │ 今天做了什么？        │  ← 备注，可选
  └─────────────────────┘
─────────────────────────
        [   确定   ]
─────────────────────────
```

- 备注**可选**，不填也能确定
- 点「＋ 确定」→ 记一条 pip（日期 = 目标日期，时间 = 此刻）→ 弹窗关闭 → 日历上立刻多一个点。「＋ 确定」固定在卡片底边，不跟着内容滚
- 第二步里可以点顶部已选模板回到第一步换一个

**目标日期怎么定**：

- 从底部工具栏的「Pip」进入 → 目标是**今天**
- 从某日的打卡列表底部「Pip一下」进入 → 目标是**那一天**（这样补记昨天就通了）

**不弹确认框**。点了确定就是记下了，没有「确定要打卡吗」。

### 7.3 某日打卡列表

**触发**：点日历上的某个日期格子。弹窗从屏幕中间浮起。

**内容**：那一天的所有打卡记录，**按时间正序**（早 → 晚，像日记）。

```
─────────────────────────
     9月22日 周一          ✕
─────────────────────────
  09:20  💧 喝水
  11:05  💧 喝水
         「开会前灌了一杯」
  14:30  🏃 跑步
         「5 公里，膝盖有点酸」
  16:12  💧 喝水
─────────────────────────
      ＋ Pip一下
─────────────────────────
```

**每行**：左侧时间（24 小时制）+ 模板 emoji + 标题；有备注时下面一行灰色小字显示备注（超过一行截断）。

**交互**：

- **点某一行** → 进入打卡详情（sheet 内容切换为详情，顶部有返回）
- **底部「＋ Pip一下」** → 打开打卡弹窗，目标日期是这一天。它固定在卡片底边，不跟着列表滚走——记录一多，原来那个位置就滑到看不见了
- 点 `✕`、点遮罩、或按返回键关闭

**空状态**：这一天没有任何记录时显示「这天还什么都没记」，底边仍然是那颗「Pip一下」。

### 7.4 打卡详情

从某日列表点某一条进入。sheet 内容整体切换为详情，顶部 `‹ 返回` 回到列表。

显示：

- 模板：emoji + 标题 + 颜色（停用的模板在标题后加灰色小字「已停用」）
- 日期与时间：`9月22日 周一 14:30`
- 备注：可直接编辑，失焦自动保存。**最长 200 字**（容量考虑，见 TECH 3.7）
- 底部：`删除`（红色文字）

**删除记录要二次确认**吗？**不要。** 删掉一条记录随时可以重新打一次，是低成本可逆操作。原则是**可逆的操作不确认，不可逆的才确认**——整个产品里只有「删除模板」需要确认。

### 7.5 模板弹窗（底部「模板」）

**触发**：点底部「模板」。屏幕中间的悬浮卡片，模板多了在卡片内部滚动。

**模板列表**：**和打卡弹窗里选模板长成一模一样**（同一套行样式，见 9.5）。顺序是**启用中**在前、**已停用**在后；停用的整行退到次级色，标题后面挂一个灰色「已停用」。

每行：emoji（没设 emoji 就是一个颜色圆点）+ 标题 + 右侧该模板在日历上的颜色圆点 + `›`。点一行进编辑。

**新建**：固定在卡片底边的一行「＋ 新建模板」，左右居中、文字用次级色——和某日列表底边那颗「＋ Pip一下」同一个处理，也和上面的列表行一眼分得开。**不用悬浮 FAB**——新建是低频动作，不该在日历上制造视觉噪音。固定在底边而不是放在列表末尾，是因为模板一多，列表末尾那行就要滑到底才够得着。

**编辑**（点某一行）：sheet 切换为编辑表单：

| 字段 | 说明 |
|---|---|
| **标题** | 必填，纯文本，最长 20 字。占位符「比如：跑步」 |
| **图标** | emoji，可选。不填则只显示颜色圆点 |
| **颜色** | 10 色预设色板，单选，排成 5 列两行 |

表单底部两个动作：

- **停用 / 恢复**：切换启用状态。停用后不再出现在打卡选择列表里，**但历史记录和日历上的点全部保留**，随时可以恢复使用
- **删除**：红色文字。**唯一需要二次确认的操作**

**删除确认文案**：

```
删除「喝水」？

这项的 34 条打卡记录也会一起删除，
无法恢复。

     [取消]  [删除]
```

**停用和删除的区别必须写清楚**（在界面上也要写），因为这是用户最容易误操作的地方：

| | 停用 | 删除 |
|---|---|---|
| 出现在打卡选择列表 | 否 | 否 |
| 历史记录与日历上的点 | **全部保留** | **一起删除** |
| 能否恢复 | 能，随时恢复使用 | 不能 |
| 需要确认 | 不需要 | **需要** |

> 停用保留了模板实体，所以**不存在「孤儿记录」**——每条记录的颜色和图标永远能解析出来。这是这个设计最省事的地方。

### 7.6 设置页（底部「设置」）

**触发**：点底部「设置」。整屏切换到设置页，左上角 `‹ 返回` 回日历。

内容：

- **主题**：三档 `跟随系统` / `浅色` / `深色`，默认**跟随系统**
- **导出数据**：下载一个 JSON 文件
- **导入数据**：选文件，然后选「合并」或「覆盖」，**默认合并**
- **导出提醒**：显示「上次导出：12 天前」，超过 30 天变红

> 主题给三档而不是两档：你要的是「能切换深浅」，但默认跟随系统仍然是对的选择——这个应用轻到不该强迫用户做一次外观决策，想固定的人再固定。

导出提醒必须常驻可见，不能藏进二级页面。数据在浏览器里而不在用户手里，清缓存、换手机、卸载都会永久消失，我没有能力代为恢复。

## 8. 数据模型（概念层）

结构定义与字段细节见 TECH 第 4 节，这里只说概念。

两个实体：

- **模板（template）**：一个可以打卡的东西。有标题、图标、颜色，可以停用（不删记录）或删除（连记录一起删）
- **打卡记录（pip）**：一次具体的打卡。指向某个模板，带日期、时刻、可选备注

**关键点：pip 是独立的记录，不是「模板在某天的状态」。**

- 同一个模板同一天可以有多条 pip
- 每条 pip 有自己的 id，可以单独编辑备注、单独删除
- 所以 pip 存成一个**记录列表**，而不是「日期 → 是否打卡」的映射

这条改动让原来的设计（日期当 key、一天一条）不再成立，但换来的是更贴合「想打就打」的模型。因为**还没有任何真实数据，不需要写迁移代码**。

## 9. UI 风格

### 9.1 设计原则

**日历是主角，颜色是唯一的装饰，其余一切退让。**

产品的个性全部由那些彩色小点承担。所以底色、文字、线条必须极度克制——一旦界面本身开始抢眼，小点就不显眼了。

四条具体准则：

1. **不用阴影做层次**，用底色深浅和留白。唯一允许阴影的是弹窗那张卡片
2. **不用边框划分区块**，用间距。发丝线只出现在「有内容从底下滚过」的那两条栏上：`顶部横幅`、`sheet 顶部导航栏`。底部工具栏没有顶边——它在正常流里，内容不会滚到它下面
3. **不用纯黑纯白**。用暖调的中性色，像纸，不像屏幕
4. **颜色归点**。界面本身只有中性色，加一处强调色（「今天」的填充圆、「Pip」按钮）；模板那 10 种颜色只出现在 pip 点上

### 9.2 色彩

**基础色板**（CSS 变量，浅色 / 深色两套）：

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `#FBFBFA` | `#131211` | 页面底色，近白（只带一丝暖）/ 暖近黑 |
| `--surface` | `#FFFFFF` | `#1E1C1A` | 弹窗、抬起层 |
| `--surface-translucent` | `rgba(255,255,255,.82)` | `rgba(30,28,26,.82)` | `--surface` 的 82%，配合背景模糊：sheet 导航栏、顶部横幅 |
| `--text` | `#1C1B19` | `#F2F0EC` | 主文字 |
| `--text-secondary` | `rgba(10,10,10,.45)` | `rgba(245,243,239,.5)` | 日期数字、时间、次要说明 |
| `--text-tertiary` | `rgba(10,10,10,.22)` | `rgba(245,243,239,.24)` | 未来日期、周表头、占位符 |
| `--separator` | `#E8E5DF` | `#2C2A27` | 分隔线（少用） |
| `--fill` | `rgba(28,27,25,.06)` | `rgba(242,240,236,.08)` | 按下态、次级填充 |
| `--accent` | `#2E6B4F` | `#6FBF95` | 「今天」的填充圆、打卡按钮、主按钮 |
| `--on-accent` | `#FFFFFF` | `#10241A` | 压在强调色上的文字 |
| `--danger` | `#C0392B` | `#E06C5A` | 删除 |

强调色选**墨绿**而不是常见的蓝：蓝太像 SaaS 后台，绿更安静，也贴合「习惯生长」的意味。深色模式下换成亮一档的绿以保证可见度。

**文字灰偏浅是刻意的**：次级 `.45`、三级 `.22` 都比常规的正文灰浅。日期数字、周表头、时间这些应该往后退，让彩色点当主角。代价是浅色底上分别只有约 3.1:1 和 1.7:1，**低于 WCAG AA 的 4.5:1**——这里优先「一眼看出这天记得多不多」，见第 12 节。

**模板色板**（10 个预设，用户单选）：

| 名称 | 色值 | | 名称 | 色值 |
|---|---|---|---|---|
| 珊瑚 | `#E8734A` | | 湖蓝 | `#4A8FBF` |
| 琥珀 | `#DFA32B` | | 靛紫 | `#7C6BB8` |
| 苔绿 | `#7A9E4A` | | 品红 | `#B955BD` |
| 青柠 | `#45AD51` | | 玫红 | `#D2607F` |
| 松绿 | `#3E8E7E` | | 石墨 | `#7A7671` |

**按色相排序**，所以色板是一段从暖到冷、最后落到中性的连续过渡；排成两行各 5 个时，
左列是暖到绿、右列是蓝到中性，各自也是一段过渡。顺序**同时是新增模板时自动分配颜色的
顺序**。全部取中明度（对浅底 `#FBFBFA` 与深底 `#131211` 的对比度都在 2.1:1 以上），
保证两套底色上都可辨识。

**为什么是 10 个而不是 8 个**：原来 8 个色在色相环上留了两个 80° 以上的空档（苔绿
86° → 松绿 168°、靛紫 253° → 玫红 344°），补上青柠和品红之后填满。**10 个色块一行排
不下**（每个可点区域 44×44，10 个要 440px），所以色板固定折成 5 列两行。

**颜色不单独承载信息**：每个色点旁边始终有模板标题，列表里也有文字。色盲用户不依赖颜色也能用。

### 9.3 字体

系统字体栈，不加载网络字体（国内加载字体太慢，且会让首屏闪一下）：

```css
--font: ui-rounded, -apple-system, BlinkMacSystemFont, "PingFang SC",
        "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif;
```

**`ui-rounded` 放在最前面**：Apple 平台上白白拿到 SF Rounded，日历数字和标题的观感主要就来自它。拿不到的平台自动回落到后面的栈，零成本、零依赖、不下载任何字体。

**日历数字和时间必须用 `font-variant-numeric: tabular-nums`**，否则 1 比 8 窄，网格和列表都会看起来是歪的。

**字号阶梯**：

| 用途 | 字号 / 字重 |
|---|---|
| 月份标题 | 25px / 700，透明度 70%（比正文轻一档） |
| sheet 标题 | 17px / 600（居中） |
| 当日列表项标题 | 17px / 400 |
| 日期数字 | 13px / 400（今天 600） |
| 时间、备注 | 15px / 400 |
| 说明 | 13px / 400；周表头 10.5px / 700，字距 .08em（小、粗、疏排，像刻度不像文字） |
| 模板行标题 | 17px / 400 |
| **输入框** | **16px（不得更小）** |

> 输入框字号低于 16px 时 iOS Safari 会在聚焦时自动放大页面，破坏布局。这是硬性下限。

### 9.4 尺寸与间距

- **间距阶梯**：4 / 8 / 12 / 16 / 20 / 24 / 32 px，只用这些值
- **页面左右边距**：16px
- **日历格子**：高 72px（下限 48px，即 iOS 触摸目标下限）。390px 屏（iPhone 14，最小目标机型）下格子内宽实测 47.2px
- **所有可点区域 ≥ 44×44px**（iOS 触摸目标下限）
- **最小目标机型是 iPhone 14**（390×844）。比它窄的屏（320px 之类）不在支持范围内，7px 的点按 390px 定尺寸
- **底部工具栏**：按钮高 50px，上下内边距 8px，再加 `env(safe-area-inset-bottom)`
- **圆角**：格子 12px，卡片 12px，弹窗卡片 20px（四角），按钮 12px，pip 为整圆

### 9.5 组件规范

**pip（日历格子里的彩色小点）**：直径 **7px**，行内和行间间距都是 **2px**，整圆。数量规则见 7.1：最多两行共 8 个，超过 8 条时第二行 5 + 3 并在末尾显示 `+N`（10px，`--text-tertiary`）。

点是页面上唯一有颜色的东西，所以点要大——取 7px 而不是 5px，让「这天记得多不多」在一臂距离外就能读出来。尺寸按 iPhone 14 的 390px 屏定的：格子内宽 47.2px，5 个点 43px。

某日列表里的色点用同一套颜色，直径 10px（列表行比格子小，点反而要大一点才看得见）。

**今天**：日期数字套一个 `--accent` 实心圆，直径 28px（`--day-circle`）——它同时也是**所有**日期数字的盒子尺寸，每个格子都要有，否则有圆和没圆的格子数字会错位。圆里的文字用 `--on-accent`。

**月份栏**：标题 25px / 700、透明度 70%（它是全页最重的一块，会跟点抢注意力）**居中**；两侧的 `‹` `›` 是 44×44 的触摸区，**贴到屏幕两侧**（容器横向不留内边距），图标再从屏幕边往内让 8px——22px 的图标框里约 7px 是笔画留白，所以笔画落在离边 15px 左右，正好和日历内容的 16px 边距对齐。标题的居中靠两侧等宽实现，切月份时不会左右跳。

**底部工具栏**：不设底色、不设顶边，和页面连成一片。三个按钮各占三分之一，每个是图标 + 文字标签的竖排组合：

- `模板`：网格图标
- `打卡`：40×26px 的**强调色胶囊**里装加号图标（笔画用 `--on-accent`），文字用 `--accent`，比另外两个突出
- `设置`：六边形套一个中心圆的图标（螺母）

图标 25px（`打卡` 那个是胶囊里的 17px）。

未激活项用 `--text-secondary`。

**弹窗卡片**：居中悬浮，宽 326px（窄屏两侧各留 32px）、高 `68vh`（软键盘弹起时由 `72dvh` 上限压下来）、四角 20px 圆角，`--surface` 底色，`0 12px 40px rgba(0,0,0,.24)` 投影——全项目唯一用阴影的地方。

**高度写死是刻意的**：切页面（某日列表 → 单条详情、模板列表 → 编辑表单）时卡片不跳，这和「日历固定 6 行」是同一个取舍。68% 是算出来的——当前所有页面里最高的是模板编辑表单（551px，含 10 色色板折行后的两行），844px 的屏上 68% 恰好不滚。**代价是内容少的页面下半张会空着**（最短的打卡第一步只有 320px）。内容更高的页面在卡片内部滚动，卡片本身不变高。

**底栏**（`.sheet-footer`）：固定在卡片底边，`flex: none`，横向内边距和内容区对齐。放主操作——某日列表的「＋ Pip一下」、模板列表的「＋ 新建模板」，以及各处的主按钮（打卡的「确定」、新建模板的「确定」）。**它和 header 不一样，底下没有内容滚过**：body 是独立的滚动容器，内容在 body 的底边就被切断了，钻不到底栏下面。所以底栏**不需要**发丝线也不需要毛玻璃，靠间距分隔就够了（见 9.1）。页面没有底栏动作时它是 hidden 的。

顶部有一个 38×5px 的圆角横条，颜色 `--separator`——**它只是装饰**：卡片居中、高度固定，它既不能拖关也不能拖改大小。导航栏高 52px（`--sheet-header-h`），底色是 `--surface-translucent` + 背景模糊，底边一条发丝线——内容会从它下面滚过。

**模板行**（打卡弹窗选模板、以及模板列表，两处共用同一套样式）：整行可点，高 44px 起、上下内边距 12px，17px 正文色。左侧一组是 emoji（17px）或颜色圆点（10px）+ 标题（超长截断）；右侧是该模板在日历上的颜色圆点（10px）——emoji 表达不了颜色，所以两个都要——以及一个 13px 三级灰的 `›`。停用的整行退到次级色。按下时整行出现 `--fill` 底色。

细边用 `box-shadow: inset` 画而不是 `border`——border 会占进盒模型，方块的内容区跟着缩水，而这里只想要一圈不改变尺寸的线。这一圈也不是 9.1 说的「用边框划分区块」：它承载的是模板颜色本身（颜色归点），不是用来分隔区域的。

**按钮**：主按钮**就是底栏那颗「＋ Pip一下」的长相**——整行铺满、强调色文字、居中、无底色，按下时整行出现 `--fill` 底色。**不做实心强调色胶囊**：那样界面上会多出一块大面积颜色，而 9.1 说的是颜色归点，强调色只留给「今天」的填充圆和底部那颗 Pip 胶囊。整行还顺带把点击区横向铺满，比一颗小胶囊好按。文字一律带 `＋` 前缀（`＋ 确定` / `＋ 新建模板` / `＋ 导入`），和「＋ Pip一下」同一个句式。次按钮为透明底 + `--text` 文字。没有描边按钮。

**主按钮一律住在底栏**（见下）：打卡第二步的「确定」、新建模板表单的「确定」、空状态里的「新建模板」。它是那一步唯一的出口，跟着内容滚就等于把出口藏起来。

**图标**：不引入图标库，全部用内联 SVG。模板的图标用 emoji，因为零成本、自带颜色、用户天然熟悉。

> emoji 在不同系统上渲染不一致，这是接受的代价——它出现在用户自己定义的位置，不一致反而不影响使用。

### 9.6 动效

克制。动效只用来解释「发生了什么」，不做装饰。

| 动作 | 时长 | 曲线 |
|---|---|---|
| 打卡后日历上 pip 出现 | 200ms | `cubic-bezier(0.34, 1.56, 0.64, 1)`（轻微回弹） |
| 弹窗卡片出现 / 收起 | 240ms | `cubic-bezier(0.32, 0.72, 0, 1)`（缩放 + 淡入，不做位移） |
| sheet 内两步之间切换 | 180ms | `ease-out` |
| 月份切换 | 180ms | `ease-out` |
| 删除记录后 pip 消失 | 120ms | `ease-in` |

**禁止**：庆祝动画、撒花、震动反馈、声音、Toast 提示「打卡成功」。记下了就是记下了。

必须响应 `prefers-reduced-motion: reduce`，此时所有位移与缩放降级为纯透明度过渡。

### 9.7 主题

**三档：跟随系统（默认）/ 浅色 / 深色**，在设置页切换。

深色模式下唯一的调整是强调色提亮（见 9.2 表），模板色板 10 色保持不变。

打卡的高频时段是晚上睡前，深色模式下打开不刺眼是真实需求，不是加分项。

### 9.8 响应式

**手机优先**，375–430px 为设计基准。

桌面（≥ 768px）：整个应用居中，最大宽度 **480px**，两侧留白。日历保持 7 列不变形，格子变高一点。

不做平板/桌面的多栏布局。这不是目标场景。

## 11. 状态与异常

| 情况 | 处理 |
|---|---|
| **首次打开（无数据）** | 不预置任何示例模板。显示空日历 + 空状态引导，让用户自己建第一个 |
| **数据加载中** | 不做 loading 转圈。先渲染空日历骨架，数据到了再填点。本地读取极快，转圈只会造成闪烁 |
| **数据解析失败** | 回退到 `pip:v1:backup`，并**进入只读状态**：所有写入被拦掉。顶部常驻一条不可关闭的横幅，给两个动作——`导出原始数据`（把原始字符串原样导出，便于事后抢救）和 `用备份继续`（确认用备份覆盖主数据，之后横幅撤掉） |
| **写入失败（配额 / 无痕）** | 顶部横幅明确提示「存储写入失败，请立即导出备份」，不要静默失败。写入恢复正常后横幅自动撤掉 |
| **打卡时没有启用中的模板** | 打卡弹窗显示空状态并引导去新建，不要让用户对着空列表发呆 |
| **模板已停用但记录还在** | 日历上的点照常显示，详情页标题后加灰色「已停用」 |
| **导入文件格式不对** | 校验 `app` 和 `version` 字段，不匹配就明确说明原因，不要静默忽略 |
| **导入合并冲突** | 默认取并集。pip 有独立 id，同一 id 取 `updated_at` 较新者 |

## 12. 可访问性

- 所有可点区域 ≥ 44×44px
- 正文对比度以 WCAG AA（4.5:1）为目标。**已知偏离**：次级灰 `.45`（约 3.1:1）与三级灰 `.22`（约 1.7:1）低于该值，这是 9.2 里刻意的取舍——要提回 AA，把次级灰提到 `.56` 上下即可；pip 等纯装饰元素不受此限
- 颜色不单独承载信息（见 9.2）
- 响应 `prefers-reduced-motion`
- 语义化 HTML：日历用原生 `<table>`（星期表头是 `<th>`，每天一个 `<button>`），按钮带可读的 `aria-label`（例如「9月22日，周一，3 次打卡」）
- 键盘可用：格子可 Tab 聚焦、回车打开当天列表。桌面不是重点，但不能不可用

## 13. 验收标准

v1 完成的判定：

1. 手机上添加到主屏幕后能全屏打开，离线可用
2. 能新建、编辑、停用、恢复、删除模板；停用后记录还在，删除后记录一起消失
3. 点底部「Pip」能在 3 次触摸内记下一笔，并出现在今天的格子里
4. **同一个模板一天能打多次，日历上显示多个点**
5. 超过 8 条时两行 5 + 3，第二行末尾显示 `+N`（N = 总数 − 8）
6. 点某天能看到当天记录（按时间正序），点某条能看详情、改备注、删记录

## 14. 待拍板

需要你确认的细节，推翻成本都很低：

1. ~~超过 5 条时显示 4 个点 + `+N`~~ **已定：点取 7px，超出时两行 5 + 3 + `+N`**（7.1 / 9.5）——原来按 5px 的点算，5 个点占满格子后放不下文字；7px 的点反而既看得清、又给 `+N` 留出了位置。7px 在 390px 屏（iPhone 14）上刚好，320px 之类的窄屏会溢出，那不在支持范围内；真要支持就把 `--pip` 调回 5px，行间距保持 2px。
2. **点按模板顺序排列**（7.1）——备选是按当天首次打卡时间排。选模板顺序是为了同一个模板每天颜色位置一致，更容易扫视。
3. **某日列表按时间正序**（7.3）——备选是倒序（最新在上）。正序读起来像日记。
4. **删除记录不二次确认**（7.4）——备选是确认。我按「可逆的不确认」原则处理。
5. **主题给三档而非两档**（7.6）——你要的是能切深浅，我加了「跟随系统」作为默认。

另外三条我按自己的判断定了，你没否决就沿用：**未来日期不可点**（7.1）、**不预置示例模板**（11）、**用 emoji 当图标**（9.5）。
