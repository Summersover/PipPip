# Pip

Pip 是一个自用打卡应用，产品目标是：**仅记录，不提醒。**

使用方式是在想记录时打开日历，在某个日期上pip一下，留下一个点作为记录。应用不提供提醒，不统计连续天数，不设定任何目标或完成度指标；记录仅陈述已发生的事实，而不制造一项待完成任务。

这条边界贯穿产品的全部设计，即无论功能如何迭代，Pip 不会出现「待办」「勾选」「未完成」这类概念。

## 产品形态

Pip 为纯静态 Web 应用（PWA），托管在 GitHub Pages 上，没有后端及账号体系。所有数据保存在用户本地浏览器中，可以通过导出和导入 JSON 文件进行迁移。部署地址为 <https://summersover.github.io/PipPip/>。

在移动端上，推荐通过浏览器的「添加到主屏幕」功能将其安装为应用使用。需要注意：iOS 将主屏幕应用视为独立的存储环境，它与 Safari 中的数据互不相通，因此请在同一个入口使用，避免记录分散在两份存储里。

## 功能

- **日历记录**：每条记录在日历上显示为一个点。同一天的点按模板顺序排列，便于扫视，超过八个时自动折叠为 `+N`。
- **两步打卡**：选择模板、写下备注，两次触摸完成一条记录，点击过去的日期可以补记。
- **模板管理**：支持新建、编辑、停用和删除。选择模板页支持拖动排序，日历与统计页的显示顺序随之调整。
- **统计**：统计页只回答两个问题，即这段时间里你做了什么、各做了几次。不设目标，也没有对比。
- **数据安全**：数据保存在本地浏览器；支持导出与导入；当主数据损坏时，应用将自动从备份恢复，并暂停写入以避免覆盖。
- **外观**：提供跟随系统、浅色、深色三种主题。

## 开发

项目没有运行时依赖，使用原生 ES 模块编写，以 JSDoc 注释配合 TypeScript 做类型检查。不引入框架和打包器；什么时候应当改变这个决定，`docs/TECH.md` 1.2 节有明确的判断标准。

```bash
npm install       # 安装 devDependencies（仅 typescript）
npm run check     # 类型检查 + 五时区测试 + sw.js 生成区域校验
npm test          # 单元测试
npm run serve     # 本地预览（localhost:8000）
```

修改 `js/` 下的代码后必须运行 `npm run check`。有几条硬性约定：相对 import 必须写明 `.js` 扩展名；日期一律使用本地时区拼接字符串，禁止使用 `toISOString()`（五时区测试会将其捕获）；`sw.js` 的缓存清单由 `npm run stamp` 自动生成，不手工编辑。

目录结构：

```
js/
  app.js      入口：装配与启动
  state.js    状态容器，写操作的唯一出口
  model.js    数据类型与纯函数
  store.js    存储层，唯一接触 localStorage 的文件
  dates.js    日期工具
  views/      各界面，只读取 state、经由 state 写入
css/app.css   唯一样式表
tools/        类型外工具：时区测试、sw 盖章、本地服务
tests/        node:test 单元测试
```

产品的设计依据与实现细节见两份文档：[`docs/PRD.md`](docs/PRD.md) 描述产品是什么、怎么用、什么风格，以及明确不做什么；[`docs/TECH.md`](docs/TECH.md) 描述如何实现。
